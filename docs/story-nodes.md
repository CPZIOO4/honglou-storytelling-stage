# 故事节点与场次继承

## 当前修正

上一版通过了动作与听闻检查，却重复讨论衣裳、成败和明早再定，没有形成行动；刘姥姥也缺少在家敢数落女婿、主动找门路的表现。旧版的工程检查不能充当叙事质量验收。

保留三维场景、纸片人物、唯一 DeepSeek 总控和生成后播放。新增 `data/storyline.json`：原著第六回提供问题与关系，AI 根据人物卡和已发生的事件连接节点。人物卡决定如何应对，上一场实际决定约束下一场。

| 节点 | 要面对的问题 | 可变化的内容 |
| --- | --- | --- |
| 家中定办法 | 怎样应付眼前生计 | 谁同行、求助还是求活计、谁留家、出发条件 |
| 门前找接话人 | 怎样获得有效回应 | 谁开口、被冷落后怎么办、是否直接获得引路 |
| 后街寻路 | 怎样找到周瑞妻子 | 问谁、谁带路；已知路线可以缩短或跳过 |
| 与周瑞妻子商谈 | 能得到哪一种帮助 | 托人引见、转话、活计线索、拒绝与条件 |
| 候见 | 怎样争取说上话的时机 | 等待、改约、误会、调整请求 |
| 说明难处 | 对方会怎样处置 | 帮助种类、数量、条件或拒绝，不固定二十两 |

节点和场景分开：同一场景可以承载多个问题；同一问题可因阻碍跨场处理。当前节点图允许有理由地绕过或返回，不等于随意跳到所有节点。重返家中不重置已发生的事。

## 生成顺序

1. 先为当前节点写完整连续交谈，独立审核逐句回应、人格、事实和决定。通过后再按自然停顿分段，没有固定3至6段或整场8句限制；单段8句是执行器上限。内容失败允许整场重写。
2. 对白确定后再编排走位和表情。编排输出不能改写台词；程序统一安排先到位、后转向说话，按字数计算显示时长。完整剧本是创作计划，不算人物已经知道的事实，个人知识仍由实际可闻对白计算。
3. 审查动作、听闻、人物在当前关系中的表现，以及是否有重复、拖延或无证据的决定。纯粹换词的复述不能算推进。允许有新理由的争执，不以字面不重复冒充戏剧变化。
4. 从实际对白提取本场决定，逐项引用事件证据。再次审核同行者是否答应、请求是否说清、条件是否真的形成。
5. 生成下一节点输入包：实际同行者、目的、对外说法、条件、承诺和每个人的听闻。全局记录只供总控，个人记忆按实际听众分开。

## 人物分场表现

刘姥姥在家不必对女婿处处陪笑：她敢批评，能算人情账，会拿乡间比方把办法说透。在府门与掌事者面前，她顾礼、试探、自嘲，也可能局促。人物特色应来自她想办成什么事、面对谁以及怎样应变，不能靠口头禅堆砌。

用户修改版原卡保持原样；运行卡的 `performance` 记录这项情境解释。刘氏可以提出办法和主动同行，狗儿是否肯去要在戏中说清，不由程序预先禁止。儿童是否同行同样取决于实际决定。

## 交接的证据与边界

`narrative.handoff` 分开记录决定、承诺与已发生事件。`party` 从当场对白提取，程序不会自动加板儿；成年同行者须听见决定，语义审核还检查实际同意。每条事实附 `evidenceRefs`，`knownBy` 由播放器的可闻规则计算。

当前 `transition` 为 `planned-not-travelled`：决定次晨一起去，不代表此刻已到荣府。下一场输入包只是准备材料，必须在演出结束且落实转场后才可推进。第一场仍是唯一接入网页播放器的场次；本轮完成节点定义、第一场生成和交接数据，不声称六场已连播。下一场还需绑定对应环境卡、入口站位、在场配角和模型后，才能实际演出。

跨场景协议准备继承资源、关系与承诺，但本轮没有实现钱财交易、道具操作或通用多场持久化存档。记录中的承诺不能当成已经执行的动作。

来源：[《红楼梦》第六回](https://zh.wikisource.org/zh-hans/紅樓夢/第006回)，以及用户人物卡、环境卡。节点与开放分支是本项目改编方案，不是原著既定结果。

## 当前呈现方式

开场仅在画面中央显示场景题字，随后退场；不保留左上角场景条或顶部说书人面板。人物先演，普通段落的编排旁白只留作内部检查。只有时间或空间省略才使用明确的 `presentation.interludes`：画面定格、模糊，稍后显示短过场文字，并可略过。当前以“一夜无话”跳过夜间，不补无剧情的夜晚动画。跳到天明不等于已经走到下一场。

姓名按用户最后选择始终放在人物头顶，使用半透明黑底、白色楷体；说话时由纯台词气泡替换。气泡尾巴、人物朝向与淡暖色光圈提示说话人与受话人，听众名单只留在后台。小屏位置作有限避让，气泡覆盖区域内的姓名暂时隐藏。

周瑞的线索归属经第六回核对：狗儿先提出父亲与周瑞有旧交，刘姥姥表示自己也知道他。运行卡不再把“知道这个人”笼统写成可倚仗的熟交；上一版曾人工校订三句对白；现已更新运行卡和自动审核，当前五段版重新由模型生成，没有人工对白补丁，来源见 `generation.authoring` 及本机调用回执。
