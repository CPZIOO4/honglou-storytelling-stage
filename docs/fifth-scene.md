# 第五场：廊前递话

入口 `?scene=waiting`，第四场结尾可继续。当前第四场的即时出行名单只有周瑞妻子；刘姥姥留在她的住处，等平儿是否肯传话的消息。第五场按这一决定开始，只配置周瑞妻子与平儿，不把条件性的后来接人变成已经带来。

## 人物与知识

依据[《红楼梦》第六回](https://zh.wikisource.org/zh-hans/紅樓夢/第006回)，平儿听周瑞妻子介绍之后，能在本职权限内安排等候、问事情轻重和传话。她有判断与分寸，不是提前知道所有事的人；她自己的候见安排不等于凤姐已经同意接见或资助。

周瑞妻子的私有经历来自第四场实际听闻。她也知道狗儿祖上与金陵王家联宗这一旧亲关系；不能把它说成自己与刘姥姥的血亲，或来客与王夫人的近亲。平儿只有实际听见转述后才知道本次来客是谁、在哪里、求什么。总控的前四场摘要不自动写入她的个人卡。

写作与独立审核都检查：问话有没有被接住、同一候见安排是否反复说、平儿是否被写成无故训诫来客的人，以及周瑞妻子是否丢掉熟悉府中事务的分寸。站姿是舞台限制，人物自然说“候着”“等回话”即可，不把执行限制念成对白。当前没有其他当值人或丫鬟加入消息链。

## 新建场景

模型由倒厅廊檐、候见长凳、影壁、青砖空地和内院入口组成，延续此前青绿瓦、灰墙、木器与像素颜料材质。人物交谈位在影壁右侧和院门外，移动绕开影壁及长凳；没有通过本场布景进入凤姐内室。

倒厅、影壁与院门的通报关系来自第六回及项目环境卡；尺寸、廊亭形式、砖纹、盆景与摆设位置属于舞台设计，不是原著建筑的逐项复原。平儿沿用桌面已认可的透明身体、背面和六种头部差分，没有重画。

- 网页模型：`assets/scene/rongfu-waiting.glb`。
- 建模源码：`scripts/waiting/build.py`，复用 `scripts/zhou_home/` 的几何与材质函数。
- 桌面交付：`红楼梦/3D场景/05_候见倒厅_v01`，包含可编辑Blender文件、GLB、源码、重新导入结果和画面检查。
- 重建时用Blender后台运行仓库脚本；从桌面存档脚本运行时，用 `-- --repo 仓库路径` 指明网页资源位置。

## 跨场状态

第五场从第四场已确认的摘要与个人经历出发。未在场的刘姥姥和家人不获得本次新对话。新记忆沿用同一分支并递增到 revision 5；任何祖先版本更换都会使旧第五场失效。

场末提取实际的立即行动者与条件性后续安排。允许安排候见、许可传话、改约或拒绝；没有听到的主人答复不能被旁白补上，也不能把不在场的人直接放入下一场。返回接人时，先通知、再同行的约定要保留，后续按真实进展落实。

接口为 `POST /api/director/generate`，提交 `{"scene":"waiting"}`；查询、完成确认和下一节点输入使用 `?scene=waiting`。本地生成稿 `.runtime/latest-waiting.json`，发布稿 `data/deepseek-fifth-scene.json`。

验证命令：`node --test tests/*.test.mjs`、`node scripts/check_model_authorship.mjs waiting`、`node scripts/check_second_scene.cjs waiting`。公开网站只播放通过检查的固定版本，本地服务可重新生成。
