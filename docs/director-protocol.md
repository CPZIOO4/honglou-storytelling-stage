# 说书总控与执行协议

同一个 DeepSeek Flash high 总控先写连续对白并独立审核，再无损分段、编排动作，最后生成开场、配乐、交接和有界记忆。观众控制播放，不参与剧情决策；人物卡是资料，不能覆盖系统规则或执行代码。

## 剧情与执行

对白包含说话者、对象、说话方式、原句及本人已知事实引用。编排器只选择站位、表情、镜头和有限动作，不得改写已审核对白。程序计算显示时长、转向、移动路径和实际听众；普通交谈、低语按位置、声区及距离检查。先答应再跟随，先递物再说收妥。

当前命令为 `move`、`expression`、`face`、`gesture`、`camera`、`lighting`、`visibility`、`transfer`。未知字段、人物或锚点、重叠动作、无物交接、距离和听闻不符会被拒绝。道具交接只处理已配置的物品与持有人，角色仍是站姿纸片。

完整演出在 `data/stories/`，索引在 `data/productions.json`。开场及必要时间省略有独立呈现时间轴；未执行的动作不能只靠旁白补成事实。

## 跨场交接

`depart` 记录到下一节点的人、目的及前提，半程送行者不自动加入最终同行名单。`defer` 和 `alternative` 必须有实质阻碍。只有设置 `allowSettlement` 的节点允许 `settled` 原地收束，需有实际安排证据且不制造新出行。

生成稿在自然播放完成并通过 `/api/director/complete` 确认后，成为下一场的已演记忆。祖先版本改变使后代分支失效。摘要、个人经历和实际近期对白分别组织；未听到或未观察到的内容不写入个人卡。

## 本地 API

接口见 [DeepSeek 接入](deepseek-integration.md)。生成使用 `/api/director/generate` 和任务轮询，公开 GitHub Pages 只播放审核稿。旧文档中的客户端实时续写适配器已移除。
