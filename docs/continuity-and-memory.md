# 剧情连续性与两层记忆

第一场从新分支开始，不读旧版的结局。Flash 先按节点写2至3段、最多8句；审核提议与同意、拒绝的具体范围、改变理由、同行名单及拖沓重复。程序拒绝对白里的冒号，不把台词改写成预先固定的句子。

运行时加载 `skills/honglou-scene-pacing/SKILL.md`；记忆生成和审核改用 `skills/honglou-character-evolution/SKILL.md`。它们是后端实际发送的规则，不要求用户在聊天界面手动触发。写作、编排、审核和辅助声音脚本统一启用 `thinking.type=enabled`、`reasoning_effort=high`；不用无效的 temperature，输出预算包含思考与JSON。记录参数、响应ID和用量，不保存推理正文。

## 人物依据

以[原文第六回](https://zh.wikisource.org/zh-hans/紅樓夢/第006回)校订当前五人的核心卡。刘姥姥在家能责备女婿、讲现实办法，到豪门前又会局促；狗儿困窘迁怒、顾脸面，听到门路才盘算；刘氏谨慎顾家，对丈夫偏克制，但自由分支允许主动提议；板儿五六岁，关注出门吃玩，不理解成人求援策略；青儿性格证据少，避免补造。原文的反应范围不等于必须复演相同行程。

狗儿提自己家的周瑞旧交；刘姥姥知道这个人，不代表这份旧交归她。人物来源与知识边界保留在 `data/cards.json`，可读导出在 `cards/characters/`。现阶段没有把后续原文“争买田地”细节强行加到所有人的开场知识中。

## 写作输入

参考 SillyTavern 的[常驻人物资料](https://docs.sillytavern.app/usage/core-concepts/characterdesign/)和[按关键词注入世界信息](https://docs.sillytavern.app/usage/core-concepts/worldinfo/)，按以下次序组织：当前环境、稳定人物卡及个人动态经历、关系知识归属、相关世界信息、总剧情摘要、不可重置的承接决定、近期对白、临近输出的简短规则。

摘要供总控安排情节，人物不能据此获知秘密。个人动态卡只能依据本人实际听闻。它可以补充承诺和新消息，不能修改姓名、身份、核心性格。审核同时看实际对白与程序算出的听闻，避免把计划写成已经完成。

历史预算按字符数明确限制：总摘要900字，每人动态卡240字，最近对白600字。旧内容被模型压缩替换，不无限追加。稳定卡与当前环境另行常驻，不随历史增长。完整动作、时间、坐标、事件引用、请求和用量保留在 `.runtime/generations/` 审计档，不作为跨场历史输入。

## 分支与确认

审核通过先保存 `contextMemory` 待播放。自然播放到末尾时，前端调用 `POST /api/director/complete`，只提交当前演出的ID；服务端保存该版本的摘要和动态卡到 `.runtime/campaigns/<storyId>/accepted.json`，重复确认不会重复追加。换一个首场版本就是另一个分支，旧稿不会污染它。确认失败会在页面提示。

`GET /api/director/next-context` 在未确认时返回 `pending-playback`；确认后返回同时含总摘要和个人动态卡的文字提示包。当前实现完成首场生成、记忆确认及下一节点输入准备；六场连续生成与播放仍未接通，不将提示包当作下一场已经演出。

## 检查

`node --test tests/*.test.mjs` 覆盖知识隔离、稳定字段保护、历史预算、100场压缩、分支隔离、重复确认、high参数与口语格式。真实生成另保留模型审核记录，再通过浏览器检查气泡、声音与全程播放；内容是否贴合用户想要的文风仍需观看评价。
