# DeepSeek Flash 本地生成

## 使用

本地运行 `启动舞台.ps1` 后打开 http://127.0.0.1:4173 。页面中的“生成第一场”请求本地后端，后端使用同一个 `deepseek-flash` 总控先写并审核完整文字剧本，再逐段编排动作。动作编排不得重写对白，转向与显示时长由程序计算；一段通过校验后才进入下一段实际舞台上下文；整场通过结构与内容审核后，页面才载入可播放结果。失败时保留现有演出。

Windows 使用 `配置DeepSeek.ps1` 输入密钥，保存位置在当前用户 LocalAppData 的 `HonglouStage/deepseek.key`，由 Windows DPAPI 加密。Linux/macOS 或其他部署可通过进程环境变量 `DEEPSEEK_API_KEY` 配置。密钥不会进入静态网页、演出 JSON 或 Git 仓库。

GitHub Pages 只能播放已经生成的静态版本。生成请求只在本机服务提供，不让公开网页携带密钥直接请求 DeepSeek。

## 本地接口

- `GET /api/director/status`：配置状态、当前任务和最近通过审核的版本。
- `POST /api/director/generate`：`{"beats":8}`，设置6至12段的预算上限，实际按节点需要生成3至上限段，返回任务 ID。一次只允许一个任务。
- `GET /api/director/jobs/:id`：查看生成与校验进度。
- `GET /api/director/latest`：只返回通过全部检查的演出。

变更请求只接受当前本机来源。生成器固定请求官方 `https://api.deepseek.com/chat/completions`，不会把客户端传入的 URL 作为 API 地址。

## 内容依据

加载 `data/cards.json` 与 `data/stage.json`，其中刘姥姥、板儿的人格和语言依据来自用户的修改版卡片；狗儿、刘氏、青儿和农家环境使用已标明来源的补充卡。旧卡中的贾母上房场次被当前农家初态覆盖。不会把已有助手示例剧情作为模型续写样本。

每段请求包含当前真实坐标、完成移动后的站位、角色各自完整听过的对白与事件 ID。总控全局摘要与人物个人听闻分开。当前场景还没作出出门决定时，板儿不会预先知道要进城。

## 审核和重试

1. 角色、站位、动作、表情、时段和台词对象按播放器协议校验。
2. 说话人到位后面向第一收话人，讲话期间不移动；悄悄话还必须同声区、近距、双方停步相向。
3. `knowledgeRefs` 只能引用说话人实际完整听到、且已结束的句子，事件格式为 `beatId:从0开始的句子序号`。
4. 检查显示时长、儿童台词、固定家具碰撞、重复无位移的 move。
5. 整场进行模型内容审查，最多两轮局部文字修订并复查，检查未知信息泄露、旁白与动作冲突和人物卡一致性；随后做实际画面检查。

同一段格式或动作失败最多退回修正两次。网络超时、认证或余额错误不自动重复调用，保留结果不确定的记录；失败稿不替换已通过的稿件。程序可把局部 `-01` 事件编号规范化为 `:0`，但仍重新计算实际听众；模型自己写的 heardBy 不作为事实。

这套检查能约束可执行性并减少内容错误，不把模型审核当成形式化的语义正确性证明。生成的段落仍应通过画面与内容检查再交付。

## 运行记录

本机 `.runtime/generations/任务ID/` 保存请求资料、模型响应正文、用量、检查结果和状态，不保存 Authorization 头或密钥，也不保存模型内部推理内容。该目录不对静态文件服务开放，且在 Git 中忽略。通过后写入 `.runtime/latest-story.json`。

服务重启不自动重放未完成任务。启动脚本负责独立本地服务，停止脚本只关闭该项目进程；关闭浏览器不会取消已经提交的生成任务。

官方协议参考：[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[Models](https://api-docs.deepseek.com/api/list-models/)。

## 已交付演出的复核

先前八段 Flash 演出共 192 秒、15 句对白，其中 4 句低语；该版本已因重复和人物失真被用户否决并替换。模型自审曾漏判私语信息泄露，后经明确反馈由模型修订相关对白；最终逐句人工复核修正了五处旁白和相关摘要，使其符合实际站位与动作。所有编辑及真实调用标识保留在演出 `generation` 中。自动审查与人工复核分别记录。

失败任务可用 `resumeFrom` 恢复已生成段落；`reviewNotes` 可提供复核意见。显式指出既有版本失败时，先撤下该版本的自动装载资格，再修订。`scripts/review_generated.mjs` 是操作员复核入口，只接受明确审核结果及旁白、摘要修改，仍重新执行结构和听闻检查。

## 故事节点修正

节点、分支及角色跨场继承见 `story-nodes.md`。旧八段演出被用户指出重复和人物失真，之前的工程通过不再当作内容验收。本轮加入整场剧本审核、对白锁定、确定性时序编排、场末决定证据与交接审核。`GET /api/director/next-context` 返回已通过审核的下一节点准备资料；它不会直接触发转场、生成第二场或使人物提前获得未来知识。
