# 架构与维护

## 单一版本与入口

`data/productions.json` 是场次的唯一入口：`parent`、`next` 及演出、运行卡、站位和人物清单路径都在这里。浏览器和后端读取同一份索引，不再分别维护名单。原有 `?scene=home`、`?scene=homecoming` 等链接保持稳定。

每场在 `data/stories/` 只保留一份当前审核稿。`data/cards/` 为运行卡，`data/stages/` 为锚点和镜头，`data/characters/` 为素材元数据，`data/audio/` 为音库。`shared/data-files.js` 提供加载器和测试的逻辑名称映射，不另建场次名单。

根目录 `cards/` 保存用户卡片、模板和考据，与机器实际加载的运行卡分开。`tests/fixtures/` 是边界条件和缺陷回归输入，不通过产品入口播放。旧版源码、素材与脚本由 Git 历史保留。

## 执行与生成

`src/app.js` 协调播放控件；`engine.js` 编译时间轴、走位和听闻；`presentation.js` 处理题字与过场；`stage.js` 渲染人物和布景；`ui/dialogue.js` 处理对白布局。渲染不修改剧情。

`backend/productions.mjs` 仅作加载分派。每场继承、人物知识、站位与分支条件在 `backend/productions/<scene>.mjs`；公共索引、版本读取与祖先校验在 `common.mjs`。`generator.mjs` 协调连续对白、审核、动作、开场、配乐和记忆，不让每位角色分别调用模型。

已完成剧情保存有界文字摘要和逐人经历。听闻采样按已编译演出缓存，查询时按对白完成时间过滤；回拖不会泄露未来信息，调用者也不能修改缓存。导入或改写剧情必须重新编译。

## 渲染与文件服务

暂停时不持续重绘。播放、拖动、镜头或窗口尺寸变化才刷新必要画面。静态布景只合并材质、属性与遮挡策略一致的不透明网格；透明物件保持独立，门框剖切仍按原逻辑切换。素材没有重画或降分辨率。角色贴图并行加载，按原人物顺序建立节点。

`backend/http/static-files.mjs` 以流发送文件，支持 HEAD、ETag 和单段 Range；客户端断开时关闭流，不为每个音频范围请求读入整份文件。

## 工具与本机目录

- `scripts/verify/`：全场播放、气泡、音频、加载恢复、来源及性能检查；入口为 `npm run verify`。
- `scripts/generate/`：开场重生成与失败记忆修复，会调用 API，仅在明确需要修订时运行。
- `scripts/assets/`：现有源素材导入、建模和音库准备；正常播放与验证不运行这些工具。
- `scripts/maintenance/clean-local.mjs`：默认只预览清理计划。使用 `--apply` 前须有完整验证，当前来源回执须齐全，本机服务须空闲；未发布的本地版本或符号链接会使清理停止。

`.runtime/` 保留当前批准稿的继续生成信息、必要来源回执和已确认记忆。完全相同的 `latest-*` 副本可删除，后端与验证工具会回退到发布稿，新生成的本地版本仍优先。`qa/` 保留最新一轮检查和性能对照证据。两者不进入 Git；密钥仍在用户目录的加密凭据文件中。

验证浏览器在完成或失败后关闭。Windows 长批次可经任务进程管理器启动，失败即停止；专用本地预览是项目保留的服务，用 `停止舞台.ps1` 关闭。
